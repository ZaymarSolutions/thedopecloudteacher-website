## Welcome
Cloud computing is renting computing capabilities—such as storage, servers, and software—over a network instead of owning and maintaining all the equipment yourself. By the end of this class, you will be able to describe common cloud services, compare deployment options, and recognize basic security responsibilities.

**Suggested duration:** 75–100 minutes, self-paced. **Prerequisites:** none. **Materials:** browser, notebook, and this packet. **Completion:** work through each activity and take the knowledge check; suggested passing score 80%.

## Lesson 1 — Cloud basics (15 minutes)
Think of the cloud like a utility: you consume resources when needed rather than building the entire infrastructure yourself. Benefits may include elasticity, rapid provisioning, and metered usage. Cloud computing is not automatically cheaper or more secure: configuration, workload, and governance matter.

**Try it:** For a neighborhood nonprofit, name one situation where on-demand computing would be useful. What might go wrong if usage increases unexpectedly?

## Lesson 2 — Service models (20 minutes)
- **IaaS:** provider manages physical infrastructure; customer manages operating systems, applications, and data. Example: virtual machines.
- **PaaS:** provider also manages much of the runtime/platform; customer focuses on application code, configuration, and data.
- **SaaS:** provider delivers an application; customer manages users, access, content, and relevant configuration.

**Interactive activity specification:** three clickable cards (IaaS, PaaS, SaaS) reveal 'You manage / Provider manages' and a concrete example. Accessible equivalent: the descriptions above.

**Practice:** A small business wants email without maintaining servers. Choose IaaS, PaaS, or SaaS and explain why.

## Lesson 3 — Deployment models (15 minutes)
- **Public cloud:** shared provider infrastructure with logical separation among customers.
- **Private cloud:** cloud environment dedicated to one organization.
- **Hybrid cloud:** integrated use of private/on-premises and public-cloud environments.

**Scenario:** A clinic keeps a legacy internal application on premises but runs a public-cloud appointment website. Which model best describes this arrangement? What data-protection questions should it ask?

## Lesson 4 — Security and responsibility (20 minutes)
The provider and customer share security responsibilities, but the division varies by service model. Customers commonly remain responsible for identities, access, data classification, and secure configuration. Apply MFA, least privilege, backups, and cost alerts as appropriate.

**Practice:** Identify two actions an organization should take before allowing employees into a cloud application.

## Knowledge check (10 minutes)
1. Which model best describes using a hosted email application? A) IaaS B) SaaS C) Private cloud
2. Which model commonly lets developers deploy code without managing the underlying operating system? A) PaaS B) IaaS C) On-premises
3. A public-cloud application integrated with on-premises systems is often called what? A) Hybrid B) SaaS C) Single-tenant
4. True/false: Using cloud services means the provider handles every aspect of customer data security.
5. Name two benefits and one potential risk of cloud adoption.

**Answer key:** 1 B; 2 A; 3 A; 4 False; 5 Possible benefits: elasticity, rapid provisioning, availability; possible risks: misconfiguration, unexpected spending, vendor dependency. Accept other technically sound responses.

## Glossary
**Cloud computing:** on-demand network access to computing resources. **Elasticity:** capacity can expand or contract. **IaaS:** infrastructure as a service. **PaaS:** platform as a service. **SaaS:** software as a service. **MFA:** multifactor authentication. **Least privilege:** giving only the access required for a task.
